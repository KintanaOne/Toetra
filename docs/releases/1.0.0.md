# Toetra 1.0.0

> Status: stable sources prepared for publication; unpublished

The `1.0.0` sources stabilize the deliberately narrow public V1 contract.
Publication remains pending. This preparation does not announce a GitHub
Release, tag, PyPI distribution, or documentation deployment and sets no
publication date. Toetra is not currently published on PyPI. Install from a
source checkout or source archive using the
[installation guide](../getting-started/installation.md).

## Stabilized scope

- Fitted single-output scikit-learn `LinearRegression` and direct fitted binary
  `LogisticRegression`, with finite, already transformed numeric features.
- Z3 reasoning over exact-real affine abstractions extracted from fitted model
  state, homogeneous `forall` or `exists` bindings, points, anchors, and domains.
- The nine-symbol public Python facade and the `init`, `validate`, `inspect`,
  `verify`, and `replay` commands through `toetra` and `python -m toetra`.
- Text, HTML, Jupyter, records/DataFrame, and JSON v6 verification reports,
  numeric and semantic evidence, provenance, manifests, and concrete replay.

The [public V1 profile](../public-v1-profile.md),
[Python contract](../contracts/public-v1-contract.md), and
[CLI contract](../contracts/cli-automation-contract.md) define the guarantees.
Incompatible public Python changes require a major version; incompatible
verification JSON changes require a schema version greater than 6. Validation,
inspection, run-manifest, and replay collections retain their v1 schema identities.

## Conclusions and limits

`PROVED`, `COUNTEREXAMPLE`, `WITNESS`, `NO_WITNESS`, and `UNKNOWN` describe the
declared property and formal abstraction. Technical execution, numeric trust,
and replay evidence remain separate. A timeout, unsupported route, or uncertain
numeric or semantic lowering cannot strengthen a logical conclusion.

There is no guarantee of global equivalence to sklearn IEEE-754 execution.
Concrete replay supplies evidence for a point; it does not prove global
floating-point equivalence. Training quality, symbolic preprocessing, deployment
behavior, multiclass and multi-output classification, nonlinear models, and
backends other than Z3 remain outside this profile. No capability is added by
this version and documentation preparation.

## Compatibility with 1.0.0rc4

Comparison against the local `v1.0.0rc4` tag shows real implementation changes
already present before stable metadata preparation:

- Model IR construction and compiler-owned affine lowering are now the default
  runtime path; an explicitly supplied `model_encoder_factory` retains the
  advanced compatibility seam.
- Model schemas and output descriptors were refactored for immutability and
  typed metadata. Non-finite affine parameters are rejected during Model IR
  construction, before numeric routing or backend translation.
- Structural parity tests compare affine lowering with the legacy encoders.

The supported routes, nine exported names, CLI commands, dependency pins, Python
constraint, and schema identities are retained. This is a statement of public
contract compatibility, not byte-for-byte implementation identity. Private
`toetra._*` APIs carry no compatibility guarantee. Version fields in reports,
diagnostics, and provenance now identify `1.0.0`; archived RC4 evidence retains
its recorded version. Replay remains subject to its existing provenance and
artifact checks; it does not rewrite archived evidence or promise equality of
all generated fingerprints across versions.

Historical details remain in the [RC4 notes](1.0.0rc4.md) and
[changelog](https://github.com/KintanaOne/Toetra/blob/main/CHANGELOG.md).

## Validation and publication gates

The CI workflow is configured to validate installations automatically on every
push to `main` and every pull request. One clean Ubuntu/Python 3.12 build produces
the reproducible wheel and sdist; eight jobs consume these same archives on
Ubuntu and native Windows with Python 3.11 and 3.12. Both formats run the same
isolated facade, resource, typing, regression/classification, replay, CLI, and
copied-quickstart checks. The
[release engineering contract](../contracts/release-engineering.md#automatic-installation-matrix)
defines the required matrix, without claiming an unexecuted workflow has passed.
Publication remains pending.

During preparation run `make ci`, `make demo-check`, and `git diff --check`.
These checks do not publish anything. Once the preparation is committed, rerun
`make release-check`, `make review-bundle-check`, and `make outside-in-check`
from the required clean checkout. Reproducible wheel/sdist builds, clean-install
probes, checksums, review evidence, and publication/rollback acceptance remain
required before any separate publication action. Do not bypass the clean-source
requirement or treat existing RC artifacts as stable artifacts.
