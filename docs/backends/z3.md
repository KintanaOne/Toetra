# Z3 Backend

> Status: Implemented for numeric affine, homogeneous multi-point verification

## Supported requests

The Z3 backend accepts:

- integer and real scalar expressions;
- typed numeric domains;
- affine model equations;
- one or more point-indexed model evaluations;
- homogeneous universal chains through refutation;
- homogeneous existential chains through witness search;
- numeric `Linf` neighborhood constraints;
- NNF/CNF/DNF forms supported by backend capabilities.

## Structured symbols

Backend identities are registered before being projected to readable Z3 names:

```text
point feature: x0.a
model output:  _model.score[x0]
```

Different points always produce different symbols. A reverse mapping is attached to results so reporting and replay never need to parse names.

For one-point results, public compatibility accessors may expose the historical unindexed output alias. Internal and multi-point artifacts always remain indexed.

## Quantifier semantics

The current profile lowers homogeneous binders to free variables under the correct verification semantics:

```text
forall ...  → search Γ ∧ R ∧ ¬P
exists ...  → search Γ ∧ R ∧ P
```

Alternating quantifiers require native quantified reasoning. They are represented in IR2 but rejected by routing and guarded again by the translator. No unsound flattening is allowed.

## Results

- universal UNSAT → `PROVED`;
- universal SAT → `COUNTEREXAMPLE`;
- existential SAT → `WITNESS`;
- existential UNSAT → `NO_WITNESS`;
- solver indeterminacy/limits → `UNKNOWN`.

Assignments include structured point/output mappings for JSON v2, grouped renderers, and replay.

## Unsupported V1 features

- string/categorical solver sorts;
- nonlinear model equations;
- alternating quantifier execution;
- non-implemented neighborhood metrics;
- preprocessing reconstruction and rich model encoders.
