# Security policy

## Supported versions

The stable `1.0.0` sources are prepared for publication; publication remains
pending. Security fixes are evaluated for this current source version and any
later version explicitly identified as supported in the repository. This policy
does not announce a GitHub Release or package distribution.

| Version | Security fixes |
|---|---|
| `1.0.0` (prepared sources; publication pending) | evaluated |
| older candidates and development snapshots | not supported |

## Reporting a vulnerability

Do not open a public issue or discussion for a suspected vulnerability.

Prefer GitHub private vulnerability reporting from the repository's
**Security** page when that feature is enabled. Otherwise, email
[KintanaOne@proton.me](mailto:KintanaOne@proton.me) with:

- the affected version or commit;
- the impact and affected boundary;
- the smallest safe reproduction;
- any known workaround;
- whether the report may be credited publicly.

Remove credentials, personal data, proprietary models, and unnecessary
artifacts before sending a report. Do not exploit the issue beyond what is
needed to demonstrate it.

The maintainer will coordinate validation, remediation, disclosure, and credit
privately with the reporter. Public disclosure should wait until a fix or
agreed mitigation is available.
